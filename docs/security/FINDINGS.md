# Security & Data-Integrity Findings (Phase S0 Audit)

**Inspected:** 18 November 2026  
**Scope:** Local checkout of `main` + uncommitted local files (`phase/s0-baseline`). Live Firebase Console deployment state is **NOT VERIFIED** because `firebase` CLI and project admin access were not executed in this baseline.  
**Policy:** No plaintext credentials, passwords, or privileged email literals are reproduced in this document.

---

## 1. Critical / High Security Findings (P0)

| ID | Severity | Location | Observed Issue | Remediation Target (Phase) |
|---|---|---|---|---|
| **SEC-01** | **CRITICAL** | `merchant-app/src/scripts/seed_d4d_data.ts:11`, `test_merchant_publish.ts:7`, `test_user_create.ts:7`, `update_real_images.ts:8`, `test_auth_and_write.ts:9-10` | Hardcoded authentication credentials (emails + plaintext passwords) are tracked in source control across multiple merchant scripts. | **S1.1:** Owner must rotate any active/reused accounts immediately. Remove hardcoded credentials from tracked scripts; use environment variables for staging-only test accounts and evaluate Git history cleanup with owner approval. |
| **SEC-02** | **CRITICAL** | `merchant-app/firestore.rules:63`, `user-app/firestore.rules:63` | `/users/{userId}` allows `allow create: if request.auth.uid == userId;` without restricting fields (`role`, `retailerId`, `isSuspended`). Any newly authenticated user can self-assign `super_admin`, `admin`, or another tenant's `retailerId` on initial document creation. | **S1.1 / S1.2:** Restrict client self-creation to allowlisted profile fields with `role == 'consumer'` (or disallow client `role`/`retailerId` creation entirely) and provision privileged accounts via trusted backend/Admin SDK. |
| **SEC-03** | **HIGH** | `merchant-app/firestore.rules:14`, `user-app/firestore.rules:14`, `merchant-app/src/contexts/AuthContext.tsx:46,56` | Privileged `super_admin` role is granted unconditionally by matching a hardcoded email address in both Firestore rules and React client code. | **S1.1 / S1.2:** Remove email-string privilege checks; replace with server-issued revocable Auth custom claims and audited admin provisioning. |
| **SEC-04** | **CRITICAL** | `merchant-app/firestore.rules:146-167`, `user-app/firestore.rules:146-167` | Top-level `notifications`, `fcmTokens`, `notificationDeliveries`, and `analytics` allow unauthenticated/public `read` and `create`/`update` (`if true`). `notifications` even allows public `update, delete: if true`. Exposes user emails/UIDs/FCM tokens and permits spam, tampering, and forged KPIs. | **S1.2 / S6:** Deny-by-default rules; restrict `fcmTokens` to owner-scoped writes via validated flow, `notifications`/`notificationDeliveries` to backend Admin SDK + scoped reads, and `analytics` writes to validated/PII-minimized flows. |
| **SEC-05** | **HIGH** | `merchant-app/storage.rules:30-43` | `/flyers/{retailerId}/**`, `/products/{retailerId}/**`, and `/retailers/{retailerId}/**` allow any authenticated user (`isSignedIn()`) to overwrite or upload files under any `retailerId` because Storage rules cannot read the named Firestore database. | **S1.3:** Mirror tenant `role` and `retailerId` into Firebase Auth custom claims via trusted backend, or route uploads through backend-signed/validated upload sessions. Separate private extraction assets from public assets. |
| **SEC-06** | **MEDIUM** | `user-app/storage.rules` vs `merchant-app/storage.rules` | Divergent Storage rulesets exist (`user-app/storage.rules` uses `(default)` Firestore lookup, `/ocr_uploads/{imageId}`, 10 MB cap, legacy roles; `merchant-app/storage.rules` uses `/flyers|/products|/retailers/{retailerId}`, 25 MB cap). | **S1.3:** Consolidate into a single canonical ruleset under `firebase/` and verify deployed rules match repository. |
| **KEY-01** | **HIGH** | `merchant-app/src/lib/flyerExtractor.ts:116,390-405`, `OcrCenter.tsx`, `OcrReview.tsx` | Gemini API key can be stored in browser `localStorage` or bundled via `VITE_GEMINI_API_KEY`, and `GoogleGenAI` (`gemini-2.5-flash`) is invoked directly from the client browser. Exposes API keys and lacks server-side rate limiting, prompt-injection isolation, and tenant ownership checks. | **S1.4 / S3:** Move Gemini calls behind a trusted backend endpoint using managed secrets, Auth/role validation, upload ownership checks, and cost/page caps. |
| **SEC-07** | **MEDIUM** | `merchant-app/firestore.rules:74-144` | `allow read: if true;` on `flyers`, `products`, `promotions`, `retailers` allows unauthenticated enumeration of `draft`, `ocr_review`, `pending_admin_review`, and `rejected` records, not just `published` ones. | **S1.2:** Restrict public reads to `status == 'published'` (and valid time window where applicable) while scoping drafts/review items to owning retailer staff and authorized reviewers. |

## 2. Data Integrity, Product Trust & Operational Findings

| ID | Severity | Location | Observed Issue | Remediation Target (Phase) |
|---|---|---|---|---|
| **DATA-01** | **HIGH** | `merchant-app/src/scripts/seed_d4d_data.ts:81-82,120-121` | Seeds synthetic branch coordinates (`25.10 + Math.random() * 0.15`, `55.15 + Math.random() * 0.20`), placeholder phone numbers, and randomized `views`/`clicks` into Firestore. | **S2:** Audit staging/prod for synthetic records; quarantine/tag demo data; reject unverified or randomized branch coordinates from distance calculations. |
| **DATA-02** | **HIGH** | `OcrAnalytics.tsx`, `RetailerAnalytics.tsx`, `AdminAnalytics.tsx`, `Dashboard.tsx` | Hardcoded charts, metrics, and fallback numbers appear alongside or in place of live data without a `DEMO / SAMPLE` label. | **S6:** Remove fabricated metrics from live views; use measured backend aggregates or explicit `DEMO / SAMPLE` mode excluded from KPIs. |
| **DATA-03** | **HIGH** | `merchant-app/src/lib/flyerExtractor.ts:217,313,345`, `OcrReview.tsx:176,180,208` | Hardcodes `confidence: 96` for Gemini Vision, `78` for Tesseract price match, `65` for grid fallback, and `75`/`50`/`100` in review UI. | **S3:** Replace arbitrary confidence percentages with explicit review reason flags (`AMBIGUOUS_PRICE`, `PACK_MISMATCH`, etc.) and benchmarked accuracy reporting. |
| **DATA-04** | **HIGH** | `merchant-app/src/pages/OcrReview.tsx:247-307` | `handleBulkPublish` uses `Promise.all(products.map(addProduct(...)))` followed by `updateFlyer`. Partial failures can leave orphan published products while the flyer remains unpublished; non-idempotent retries create duplicate product docs. | **S3:** Move publication to a server-side atomic/idempotent batch or generation-pointer publish gate with pre-publish validation. |
| **DATA-05** | **MEDIUM** | `user-app/app/src/main/java/com/example/data/FirestoreDealFinderDao.kt:15,32,39,51,63,75,87,145` | Core queries (`getStores`, `getFlyers`, `getProducts`, `searchProducts`, `searchStores`, `searchFlyers`, `getCoupons`, `getPromotions`) hardcode `.limit(100)` without pagination or incomplete-coverage indicators. | **S5:** Implement scoped/paginated queries and explicit coverage metadata. |
| **DATA-06** | **HIGH** | `user-app/app/src/main/java/com/example/ui/DealFinderViewModel.kt:37-40` | `products` flow filters `status == "published"` but does **not** filter expired products (`validTo > currentTime`), unlike `flyers`, `coupons`, and `promotions`. | **S4 / S5:** Enforce `validFrom`/`validTo` eligibility consistently across queries, ViewModel, and basket engine. |
| **UX-01** | **HIGH** | `user-app/app/src/main/java/com/example/ui/lists/ListScreen.kt:195-223,478-600` | Empty shopping list renders 4 hardcoded `DemoListItem` rows and hardcoded `BudgetCard` (`AED 500.00`, `AED 42.30` saved) and `BestBasketPriceCard` (`At Nesto Hypermarket`, `8 items`). | **S4 / S5:** Replace with genuine empty state and optional clearly-labeled sample basket; compute cards strictly from real basket state. |
| **UX-02** | **HIGH** | `user-app/app/src/main/java/com/example/ui/compare/CompareScreen.kt:340,351,624,648,654` | Falls back to `allProducts.take(10)` when filtered search is empty; substitutes `1.2 km` when distance is null; fabricates strike-through `oldPrice` as `currentPrice * 1.25`; falls back store name to `"Nesto Hypermarket"`. | **S4 / S5:** Show honest empty state, `"Distance unavailable"`, omit strike-through when `oldPrice` is absent, and never invent retailer names. |
| **UX-03** | **CRITICAL** | `user-app/app/src/main/java/com/example/ui/lists/BasketOptimizationEngine.kt:74-160`, `DatabaseEntities.kt:72-136` | Uses `item.name` as map key; substitutes `targetPrice` for missing items to compute a complete basket total; uses `2.5 km` / `+1.5 km` fallback distances; relies on permissive token-overlap `isIdenticalTo()` without strict SKU/pack/unit enforcement. | **S4:** Extract pure domain `BasketOptimizer` using integer fils, strict SKU/pack matching, `UNPRICED` handling (`totalFils = null` when incomplete), and explicit coverage/baseline disclosures. |
| **MSG-01** | **HIGH** | `merchant-app/src/pages/Notifications.tsx:44-96` | Writes `status: 'sent'` to `notifications` and `notificationDeliveries` after querying `fcmTokens`, without actually sending any FCM message via Firebase Admin SDK. | **S6:** Dispatch via trusted backend Admin SDK, track real `accepted_by_provider` / `failed` statuses, and honor user opt-in preferences. |
| **GOV-01** | **HIGH** | `D4D/` directory & `seed_d4d_data.ts` | Scraped third-party flyer/shop assets (`D4D.apk`, `D4D/catalogues.json`, `D4D/shops.json`) lack documented redistribution/licensing rights for public production publishing. | **S2:** Require documented permission basis (`sourceType`, `permissionBasisRef`) before publishing any non-demo offer; isolate `D4D` assets from production. |
